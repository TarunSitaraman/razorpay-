Yukti

the recovery agent that knows when to stop

Revenue at risk

Four kinds of revenue leak — failed payments, abandoned carts, failed subscriptions, overdue invoices. Four separate tools today. One customer.

Measured money — five arms, identical cases

Every arm runs the same allocator, stopping rules and policy engine. Only the number being optimised changes, so any difference is the objective and never the plumbing. The arm that recovers the most is not the arm that earns the most.

Run make eval to produce this.

Stopping rules — work deliberately not done

Stopped and not-funded are reported apart. One is a decision that this money is not worth chasing; the other is a budget that ran out with the case still open. Adding them would overstate what the system walked away from.

Budgets

Hard limits, enforced by the database rather than by arithmetic. A per-customer cap applies across every surface — which is what a per-agent budget cannot see.

Policy — what was blocked, and by which rule

Decision feed

Every other recovery product can tell a merchant what it did. This one can tell them what it declined to do, and which rule declined it.
